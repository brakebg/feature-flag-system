# ESC-002: Two Admin API status choices the spec leaves open
Status: resolved
Trigger: 2 (touches the API contract, sections 6 and 9.1)
Milestone / gate / AC: M2 / - / ERR-PATCH-/admin/flags/{flagId}-400
Raised: 2026-10-04T12:36:20Z at commit 2620c39

## What happened

The M2 audit (spec-auditor SA-2, SA-3) found two Level 1 decisions that set API behaviour.
The spec does not decide them. They are raised together at the M2 boundary (12.5 step 7).

1. **`PATCH /flags/{flagId}` with `"enabled": null` (D-011).** Spec 4.2 item 4 covers null for
   *required* fields; `enabled` is optional in PATCH. Current: 400 `validation`, field `enabled`
   (same rule as `"name": null` in 6.1). An omitted `enabled` stays unchanged.
2. **Unsupported HTTP method on a known path (D-012).** Example: `PUT /api/v1/admin/groups` with an
   admin token. Spec 9.1 has no 405 row and says `type` always uses a suffix from the table.
   Current: 404 `not-found`.

## Evidence

M2 audit findings SA-2, SA-3. Code: `UpdateFlagRequest`, `GlobalExceptionHandler`.

## What was tried

Nothing to try: these are open questions, not failures.

## Options

A. Keep both as they are now (recommended): `enabled: null` → 400 `validation`; unknown method → 404 `not-found`.
B. `enabled: null` → 400 `malformed-request` (treat null as a wrong JSON type); unknown method → 404 `not-found`.
C. Keep 1 as now; unknown method → 405 with type `malformed-request` (status not in the 9.1 table).

## Recommendation

A. Both follow existing spec rules (6.1 null name; 9.1 only known suffixes).

## Blocked meanwhile / continuing with

Not blocking. The current behaviour stays; no tests depend on it outside `GlobalExceptionHandlerTest`
and `RequestValidationTest`. Continuing with M2 audit fixes and M3.

## Question (one, answerable with an option letter)

Do you accept A, or B / C?

## Answer (filled in when resolved)

Owner, 2026-10-04 (PR comment, answer to 5979985454): **A**.
`PATCH /flags/{flagId}` with `"enabled": null` -> 400 `validation`; an unsupported method on a
known path -> 404 `not-found`. Recorded in D-011, D-012, D-040. No code change.
