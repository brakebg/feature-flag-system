## What happened

The M5 audit (spec-auditor SA-1, SA-4) asks to confirm two gate details.

1. **PIT runs are not test results (D-024).** PIT re-runs the unit tests against mutants. Those
   runs must not reach the gate 14 tag log (a killed mutant is a failing run by design). PIT gets
   `-Dff.tags.off=true`; the tag listener skips recording when it is set. Normal test runs are
   recorded as before.
2. **Gate 11 "readiness was DOWN before warm-up" (D-025).** The DOWN window lasts a few
   milliseconds with the small seed (spec 11.4: "The DOWN period is short"), so a polling client
   often cannot see the 503. The step passes when a 503 is seen, or when the backend's own
   readiness transitions are logged in this order: REFUSING_TRAFFIC → cache warm-up finished →
   ACCEPTING_TRAFFIC, and the probe then answers 200. The backend integration test
   (`EvaluationIT.readinessIsDownUntilWarmUpHasFinished`) holds the warm-up and proves the 503.
