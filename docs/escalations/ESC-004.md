# ESC-004: Token endpoint error order and env-variable clients
Status: resolved
Trigger: 2 (security model, section 5)
Milestone / gate / AC: M3 / - / AC-EVAL-2
Raised: 2026-10-04T13:35:12Z at commit b0aec95

## What happened

The M3 audit (spec-auditor SA-2, SA-4) found two choices in section 5 that the spec leaves open.

1. **Error order of `POST /api/v1/auth/token` (D-018).** When a request has several problems, the
   order decides the error code. Current order: (a) content type not form → 400 `invalid_request`;
   (b) client authentication → 401 `invalid_client`; (c) missing `grant_type` → 400
   `invalid_request`, other grant → 400 `unsupported_grant_type`; (d) scope → 400 `invalid_scope`.
2. **`FF_AUTH_CLIENTS_<n>_CLIENT_ID` / `_CLIENT_SECRET` / `_SCOPES` (5.1).** Current: when any of
   these variables is set, they define the whole client list and replace the list from
   `application.yml` (so `order-service` is gone unless it is also given). Indexes must start
   at 0 without gaps (Spring list binding). `_SCOPES` is comma-separated.

## Evidence

M3 audit SA-2, SA-4. Tests: `TokenEndpointIT`, `AuthPropertiesTest.clientsCanComeFromFfAuthClientsEnvironmentVariables`.

## Options

A. Keep both as they are (recommended).
B. Item 1: client authentication first (401 before any 400), item 2 as now.
C. Item 2: env clients are appended after the configured list (indexes continue after the yml entries).

## Recommendation

A. Item 1 follows RFC 6749 practice for unparseable bodies; item 2 is the plain Spring binding,
the same as `featureflags.auth.clients[n]` would do.

## Blocked meanwhile / continuing with

Not blocking; continuing with M4.

## Question (one, answerable with an option letter)

Accept A, or B / C?

## Answer (filled in when resolved)

Owner, 2026-10-04 (PR comment, answer to 5980558255): item 1 **A**, item 2 **C, modified**.
1. Keep the error order as it is (D-018).
2. Env clients are appended after the clients from `application.yml` (`order-service` stays).
   Env indexes start at 0 (`FF_AUTH_CLIENTS_0_CLIENT_ID` is the first env client). The fail-fast
   rules (duplicate client id, blank secret) apply to the merged list.
Applied test-first in D-040 (`AuthPropertiesTest`, `EnvClientsIT`).
