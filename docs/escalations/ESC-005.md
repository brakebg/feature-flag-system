Raised: 2026-10-04T16:22:18Z at commit 400b82a

## What happened

The M4 audit (spec-auditor SA-2, SA-3) found two Level 1 choices that touch a gate or the API.

1. **Gate 7 runs PIT with the unit tests only (D-020).** `targetTests` is
   `com.example.featureflags.*Test` (not the Testcontainers `*IT` tests) and `threads` is 4.
   The mutated packages (auth, group, flag, evaluation) and the 60 % threshold are as the spec says.
   With the ITs each mutant would start a database and a Spring context (hours per run).
   Score now: 91 %. This makes the gate harder, not easier.
2. **Which 409 wins (D-021).** When a create request is both a duplicate key and over the limit,
   the API answers `duplicate-key` (checked first), not `limit-reached`. Spec 6.1: "409 on POST
   means `duplicate-key` or `limit-reached`" without an order.

## Options

A. Keep both (recommended).
B. Item 1 as now; item 2 limit first (`limit-reached` wins).
C. Item 1: PIT also runs the `*IT` tests (gate 7 then takes hours); item 2 as now.
