# ESC-001: Release version needs a one-line change in backend/pom.xml
Status: resolved
Trigger: spec 005 section 8 "A change would break an item of section 3" (section 3 item 4); escalation.md trigger 1 (spec conflict)
Milestone / gate / AC: M12 / gate 15 / release (spec 005 sections 8 and 9, deployment.md 9.6)
Raised: 2026-10-20T13:23Z at commit 15497d2

## What happened
Spec 005 asks for a release with the next free minor version (section 8 phase C, section 9,
section 10 item 5). `VERSION` on main is 1.1.0, so the release is 1.2.0.
Gate 15 (`scripts/check-integrity.mjs`) requires `backend/pom.xml` `<version>` and
`frontend/package.json` `version` to equal `VERSION` ("Must equal the root VERSION file").
Spec 005 section 3 item 4 says "No backend file changes", and `spec.json` scope has no
`backend/**`. So the release cannot be made without changing one line in `backend/pom.xml`.

## Evidence
`scripts/check-integrity.mjs` lines 167-171: `backend/pom.xml version ... differs from VERSION`.
Spec 002 (release 1.1.0) changed `backend/pom.xml` `<version>` the same way.

## What was tried
Nothing changed. The version bump is parked; everything else of M12 continues.

## Options
A. Change only `<version>1.1.0</version>` to `<version>1.2.0</version>` in `backend/pom.xml`
   (with `VERSION`, `frontend/package.json`, `CHANGELOG.md`). No code or behaviour change;
   `/actuator/info` `build.version` becomes 1.2.0, which 9.6 requires to equal the UI footer.
   `backend/openapi.json` stays the same (its info version is `v0`).
B. No release in this PR: `VERSION` stays 1.1.0; the owner releases later. The definition of done
   item "VERSION and CHANGELOG.md for the next free minor version" stays open.

## Recommendation
A. It is the release the spec asks for; the pom line is version metadata, not backend code.

## Blocked meanwhile / continuing with
Blocked: the version bump and the `M12: complete` commit. Continuing: milestone audit and fixes.

## Question (one, answerable with an option letter)
May the builder change the `<version>` line of `backend/pom.xml` to 1.2.0 for the release (A),
or should this PR make no release (B)?

## Answer (filled in when resolved)
A (owner, 2026-10-20). Change only the `<version>` line of `backend/pom.xml` to 1.2.0, with
`VERSION`, `frontend/package.json` and `CHANGELOG.md`. Recorded in SPEC.md section 3 item 4 and
section 10 item 9; `backend/pom.xml` added to the `spec.json` scope. Owner amendment
`spec-005-amend-2`.
